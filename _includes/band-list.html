{% comment %} Collapsible provider list grouped by rating band. Used by every listing that shows providers — use cases, features, VC portfolios, secondary market, and the providers/APIs indexes. The ordering contract is set in scripts/lib_rating.py: bands descending (exemplar → minimal, unrated last), composite descending inside a band, then A–Z. Exemplar and Strong render OPEN; everything below renders CLOSED, because on a list of thousands the long tail is noise until it's asked for. That choice lives in lib_rating.BANDS_OPEN_BY_DEFAULT and arrives here as `group.open`. Two ways to hand it the rows. Most callers pass `group.items` as full row hashes and that is it. The tag pages can't: there are ~275,000 (tag, provider) pairs, so a full row per pair is ~200 MB of data. They pass slug STRINGS in `group.items` plus a shared `rows` lookup table, and the join happens here. EVERY ROW IS A FOUR-COLUMN GRID, and each cell declares its OWN column in band-list.css.html rather than relying on auto-placement. That is the fix for the jumble on /tags//: the row emits up to four cells (name, middle, meta, glyph) but the grid declared only three tracks, so on a rated provider the K'in sun wrapped onto a second line underneath the name, and on a provider with no description the meta cell slid left into the description track. Cells are optional and the column each one lands in is not, so a row missing any of them still lines up with every other row in the group. Params: bands - array of {band,label,blurb,open,count,items} from group_by_band() rows - OPTIONAL slug -> row map. When present, each `items` entry is read as a slug into it instead of as the row itself. link_base - URL prefix for each item (default /providers/) layout - OPTIONAL 'kin' to lead each row with the K'in sun: sun | name | tags | score. The default keeps the network's shared listing anatomy — name | description | meta | sun — because 30+ capability sites and apievangelist.com render the sun on the far right. Only the column ORDER changes; the markup is identical either way, so nothing else has to branch. omit_tag - OPTIONAL tag label to leave OUT of every row's tag chips. A tag page passes its own name: every provider on /tags/video/ is tagged Video, so repeating it 1,000 times says nothing and eats the width the other tags need. more_url - OPTIONAL destination for the "see them all" link a capped group shows empty_text - shown when there are no items at all The middle cell shows `item.tags` when the row carries them and falls back to `item.description`. Tag chips are plain text, never links: the whole row is an , and a nested anchor is invalid HTML that browsers silently unnest. {% endcomment %} {% assign _base = include.link_base | default: '/providers/' %} {% assign _rows = include.rows %} {% if include.layout == 'kin' %}{% assign _variant = ' band-list-kin' %}{% else %}{% assign _variant = '' %}{% endif %} {% assign _omit = include.omit_tag %} {% if include.bands and include.bands.size > 0 %}
