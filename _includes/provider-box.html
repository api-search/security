{%- comment -%} provider-box.html — one artifact section on a provider detail page. Every artifact box on the provider page renders through THIS include so the shape is identical everywhere: a heading with the live count, a one-line summary of what the box is, then a card grid that is ALWAYS a scroll-pane (capped at ~two rows) so one prolific provider can't push the page down. Keeping the card markup in one place is deliberate — the provider template used to hand-repeat ~20 near-identical blocks, which is exactly how the per-section scroll-pane conditions drifted (APIs keyed off json_structures, MCP off examples, …). One include, no drift. Parameters: id anchor id (also the #id the TOC chip jumps to) [required] title section heading text [required] items the array to render [required] provider_slug page.slug — first path segment of each card link [required] blurb one-line description of the box [optional] path link base: card title -> /{{path}}/{{slug}}/{{item.slug}}/ omit for plain-text items (features, use cases) [optional] badge badge label shown on each card (uppercase) [optional] color accent colour — card left border + badge background [optional] Item fields understood (all optional, first match wins for the meta line): name / description / summary_line, and one count of: class_count(+property_count) / property_count / scope_count / plan_count / limit_count / operation_count(+acting_count) / key_count. A bare-string item (a raw feature/use-case) renders as its own label. {%- endcomment -%} {%- if include.items and include.items.size > 0 -%}
