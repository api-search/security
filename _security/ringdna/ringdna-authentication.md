schemes:
- client_authentication: none
  dynamic_client_registration: true
  flows:
  - authorizationUrl: https://app.ringdna.com/mcp/oauth/authorize
    code_challenge_methods:
    - S256
    flow: authorizationCode
    issuer: https://app.ringdna.com
    pkce: required
    refresh_token: true
    registrationUrl: https://app.ringdna.com/mcp/oauth/register
    scopes:
      mcp: Access the RingDNA MCP server.
    tokenUrl: https://app.ringdna.com/mcp/oauth/token
  method: probed
  name: mcp-oauth
  notes:
  - The only machine-negotiable authentication Revenue.io publishes.
  - Anonymous dynamic client registration returns 201, so an agent can self-register.
  - Undocumented in the Knowledge Center; discovered by well-known probe.
  source: https://app.ringdna.com/.well-known/oauth-authorization-server
  surface: MCP server (https://app.ringdna.com/mcp)
  token_presentation: Authorization Bearer header
  type: oauth2
- binding: The API Key and API Secret are bound to the customer's Salesforce Organization ID. Refreshing a partial-copy Salesforce sandbox can change the Org ID, which invalidates the credentials until Revenue.io Support updates the Org ID on the account.
  credentials:
  - API Key
  - API Secret
  entry_point: Salesforce App Launcher > Guided Selling by Revenue.io > Settings > Setup; paste API Key and API Secret and Save.
  method: searched
  name: guided-selling-api-credentials
  notes:
  - This is a sales/support-gated credential. There is no developer portal, no key self-service, and no published key rotation policy.
  - Valid credentials gate nearly all Guided Selling functionality including sending emails, executing template actions, and permission confirmation.
  provisioning: Not self-service. Credentials are generated by the customer's Revenue.io Implementation Manager or the Support team and handed over out of band.
  scopes_documented: false
  source: https://support.revenue.io/guided-selling/salesforce-administration/installation-and-setup/setup-api-credentials/
  surface: Guided Selling managed package (RDNACadence) to Revenue.io servers
  type: apiKey
  validation: Acceptance is confirmed by a message on the Setup page and by the Users tab populating with every user holding a Guided Selling license.
- flows:
  - authorizationUrl: https://login.salesforce.com/services/oauth2/authorize
    flow: authorizationCode
    refresh_token: true
    scopes:
      api: Access the current logged-in user's account using APIs such as REST API and Bulk API 2.0. Includes chatter_api for Connect REST API.
      refresh_token: Return a refresh token so the application can interact with the user's data while the user is offline (equivalent to offline_access).
      web: Use the access_token on the web. Includes visualforce for customer-created Visualforce pages.
  identity_provider: Salesforce
  method: searched
  name: salesforce-connected-app-oauth
  notes:
  - Revenue.io is registered as a Salesforce OAuth Connected App; this is the authentication that actually carries production traffic.
  - Because all data flows through the customer's Salesforce org, the effective authorization model is Salesforce profiles and permission sets, not a Revenue.io scope system.
  prerequisites:
  - The Salesforce user profile must have "API Enabled" checked, or login fails with [API_CURRENTLY_DISABLED].
  - Salesforce SSO is supported for dialer sign-in.
  revocation: Users and administrators can revoke Revenue.io's access at any time from Salesforce.
  source: https://support.revenue.io/integrations/salesforce/common-salesforce-errors/oauth-access-scope/
  surface: RingDNA Communications Hub / Revenue.io platform to the customer Salesforce org
  type: oauth2
