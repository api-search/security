  header: Authorization

  location: header
  name: Standard Virtual Key
  type: apiKey
- evidence: 'Send it in X-Archestra-Virtual-Key , next to the provider''s own credential:'
  header: X-Archestra-Virtual-Key
  how_to_obtain: Create a passthrough virtual key in the LLM Proxy UI, copy the key, and include it in the X-Archestra-Virtual-Key header.
  location: header
  name: Passthrough Virtual Key
  type: apiKey
- evidence: Get a token. It lasts one hour.
  how_to_obtain: Create an OAuth client in Settings → OAuth Clients, then request a token via POST to the token URL with grant_type=client_credentials, client_id, client_secret, and scope.
  name: OAuth Client (client_credentials)
  scopes:
  - llm:proxy
  token_url: https://<archestra-host>/api/auth/oauth2/token
  type: oauth2
- evidence: Run the authorization code flow with PKCE. Ask for scope=llm:proxy . Add offline_access to get a refresh token.
  how_to_obtain: Configure redirect URIs for the OAuth client, then perform the standard OAuth 2.0 authorization code flow with PKCE to obtain an access token.
  name: OAuth Client (authorization_code)
  scopes:
  - llm:proxy
  - offline_access
  type: oauth2
- evidence: 'Send the JWT as Authorization: Bearer on a provider route.'
  header: Authorization
  how_to_obtain: Add an OIDC provider under Settings → Identity Providers, then use the issued JWT as a Bearer token in the Authorization header.
  location: header
  name: Identity Provider JWT
  type: http-bearer
